# Contributing

Thanks for considering a contribution. A few rules keep the list useful.

## What belongs here

- Skills for Claude (Claude Code, Claude apps, or the API via Agent Skills).
- Tools that help you author, validate, or package skills.
- Docs, posts, or videos that teach something specific — not general "intro to Claude" content.

If it's an MCP server, it probably belongs in [awesome-mcp-servers](https://github.com/punkpeye/awesome-mcp-servers) instead. If it's a Claude Code plugin that doesn't ship skills, [awesome-claude-code](https://github.com/hesreallyhim/awesome-claude-code) is a better fit.

## Entry format

One line per entry:

```
- [name](url) — one-line description.
```

- Use the project's real name, not a marketing tagline.
- Describe what it does, not how great it is. Drop adjectives like "powerful", "comprehensive", "seamless".
- No affiliate, referral, or tracking links. Direct GitHub or the project's own domain only.
- Keep descriptions under ~120 characters where you can.

## Ordering

Within a section, order is rough popularity / usefulness. If you're not sure, put new entries at the bottom of the section and I'll sort on merge.

## Quality bar

- The skill must actually work. If it's broken or abandoned, note it in the description or don't submit it.
- Forks of another skill with only cosmetic changes don't belong here.
- One entry per project. If a repo contains many skills, link the repo once, not each skill.

## Submitting

Open a PR with your change. The PR body should cover:

- What it is (one sentence).
- Why it's worth listing (one sentence, optional but helpful).
- Whether you're the author (fine either way, just say so).

Small PRs merge faster. One entry per PR is ideal when the list grows.
